# Decisions

- **2026-10-28 Process model:** the app processes (Next.js and the worker) run under PM2 on the host. Docker is used only for stateful services. This keeps deploys fast and simple, and the logs and restarts go through PM2.
- **2026-10-28 Workspaces = Better Auth organizations:** the `workspaces`, `members` and `invitations` tables follow the organization plugin's field names. The tables are renamed through the adapter's modelName mapping.
- **2026-10-28 Deploy installs dev deps:** `pnpm install --prod=false`, because `.env` sets `NODE_ENV=production` and the build needs TypeScript and Tailwind.
- **2026-10-28 Backups via BullMQ scheduler:** the backup job runs from the worker instead of a system cron, so it shows up in the queue dashboard. A cron fallback is documented in DEPLOY.md.
- **2026-10-28 Roles:** Better Auth's default access control is extended with a `guest` role that has no organization permissions. Record-level rules live in @mewe/core (M4).
- **2026-10-28 Email before React Email:** `lib/email.ts` sends simple inline-HTML emails through Resend. When no API key is set, it logs to the console so local development works without an email provider. React Email templates replace these in M12.
- **2026-10-28 OAuth buttons are build-time:** the sign-in and sign-up pages are prerendered, so Google and GitHub buttons appear according to the env present at build time. The deploy hook sources `.env` before building, so this matches production.
- **2026-10-28 Built the public site before M2:** Stripe keys aren't available yet, so the website, catalogue and SEO work (normally M3, M5b and M10) was done first.
- **2026-10-28 Catalogue licence exclusions:** Invoice Ninja (Elastic License v2), Akaunting and Outline (BSL) and n8n (Sustainable Use) were dropped because their licences forbid selling hosted versions. Kanboard (MIT) and Jorani (AGPL-3.0, hosted unmodified with a source link) carry over from the old site.
- **2026-10-28 Legacy URL strategy:** old product ids and demo folders map to new app slugs in @mewe/core (`legacyProductSlug`, `legacyAppDirSlug`) and are served as 301/308 redirects. Old Insights URLs redirect temporarily to the homepage until quality-gated content exists.
- **2026-10-28 Theme:** class-based dark mode via next-themes (default: system), with CSS variables in globals.css.
- **2026-11-10 Company/product URLs:** workspaces live at `mewemarket.com/{company}` and apps at `mewemarket.com/{company}/{product}` (workspace pages: `/{company}/apps|tools|billing|settings`). The page files stay under `app/w/[slug]` and `app/w/[slug]/a/[app]`; middleware rewrites the public path onto them and 308-redirects old `/w/...` links. Company addresses may not use a top-level route or kept-back word (`RESERVED_SLUGS` in `@mewe/core/urls`), enforced in Better Auth's organization hooks; app slugs may not use the workspace page names. Workspace pages send `noindex` because robots.txt cannot list every company.
- **2026-11-12 Hosted apps, starting with Twenty CRM:** the owner wants full, well-known open-source products inside the suite, not only records-engine apps. The CRM is Twenty (AGPL-3.0) in multi-workspace mode: one server, one Twenty workspace per MeweMarket workspace at `{company}.crm.mewemarket.com`, shown full-size at `/{company}/crm`. Twenty cannot run under a sub-path (root-relative assets), and its SAML/OIDC SSO is Enterprise-only, so sign-in uses only its public GraphQL API: each person gets a Twenty user with a random password stored encrypted (`hosted_accounts`), and MeweMarket issues a one-time login token. A platform account (Twenty's first user, so server admin) creates and administers the workspaces; membership and roles are mirrored (`hosted_members`) and synced from the Better Auth organization hooks plus an after-hook on `/organization/leave`. Framing uses Twenty's own `allowedEmbeddingOrigins`. Free Twenty caps a server at 5 workspaces; the owner will buy an Enterprise key when a 6th company needs it (until then the install shows a friendly "full" message). The old records CRM moved to the slug `contacts` ("Contacts & Deals"), with a data migration.
- **2026-11-12 Invoices, Projects and Helpdesk as hosted apps:** InvoiceShelf (AGPL-3.0, multi-company), Plane Community (AGPL-3.0, multi-workspace) and Chatwoot's community image (MIT, multi-account), each checked by running it: no company cap (unlike Twenty), API to create companies and members, sign-in without a second login, framing and session-ending on removal. Invoice Ninja and Akaunting stay excluded (licences). Providers implement one interface (`packages/core/src/hosted/types.ts`). InvoiceShelf and Plane have no login-link API, so MeweMarket signs in server-side and passes the session cookie through `/api/hosted-sso`, served by MeweMarket on the product's host via the proxy (host-only cookie, encrypted one-minute single-use ticket in Redis); no product code is changed. Products that show a user every company it belongs to (InvoiceShelf, Plane, Chatwoot) get one account per person per company (`hosted_accounts.scope`). Removal ends sessions: InvoiceShelf and Chatwoot by deleting that account, Plane by also rotating its password, Twenty by removing the member. Full apps take the plain slugs (`crm`, `invoices`, `projects`, `helpdesk`); the records apps moved to `contacts`, `quick-invoices`, `simple-projects`, `simple-helpdesk` with a data migration.
- **2026-11-12 E-Signatures (Documenso); Cal.com and Mattermost not used:** Documenso (AGPL-3.0, v2.21.1) runs with billing off, where it has no document, team or member limits. Owner/admin map to organisation MANAGER (team admin, but cannot delete the organisation). It has no API to create a user with a password, so the provider reads new users' reset tokens through a role limited to `SELECT` on `PasswordResetToken` (owner-approved). **Open legal question:** the unlimited self-hosted behaviour comes from limits code in Documenso's commercial `packages/ee`, compiled into the standard image; confirm with Documenso or counsel before launch. Cal.com was dropped (company spaces are in its commercial /ee; the MIT Cal.diy has none and is "not for production"); Mattermost Team Edition was dropped (unlicensed servers stop at 250 active users in total). Team chat: Zulip being checked; bookings: Easy!Appointments found workable with a router, pending the owner's decision.
- **2026-11-12 Bookings (Easy!Appointments), path-based; Team chat paused:** the owner wants no per-company subdomains, so bookings live on the main site at `/{company}/book/` (public page) and are shown at `/{company}/bookings`. Easy!Appointments (GPL-3.0, 1.6.1) is single-company; our router (`infra/easyappointments/`) serves every company from one container with one database each, the company named by the proxy (shared secret), cookies on `Path=/{company}/book/`. Same origin as MeweMarket, so no frame-header changes; the sign-in bridge gained `cookiePath`, and the bridge URL is always the product's origin. `book` is a reserved app slug; the proxy skips the site's own sections. The records app moved to `simple-bookings` (migration 0005). Zulip (team chat) works but needs per-company subdomains, container command access and ~2.5 GB RAM: the owner paused it.
- **2026-11-12 Security pass on all hosted apps (AI agents as users and attackers):** isolation between companies held in all six. Fixed: Bookings moved off MeweMarket's origin to book.mewemarket.com (critical: script in Easy!Appointments could read the MeweMarket session); Twenty company admins get a restricted custom role and the public invite link is off, with a sweep for unknown members (high: outsiders could join via the invite hash; admins could demote the platform account); container egress firewall (SSRF via product webhooks); rate limits on app sign-ins, e-signature sending, booking submissions and public chat endpoints; no-script policy on invoice PDF previews; ticket host checked before use; CRM per-person cap. Accepted for now: products' own per-company storage quotas (the 150 GB cap and upload limits bound the total), InvoiceShelf company admins can't use its user/company settings pages (MeweMarket manages those).
- **2026-11-12 AI apps: AI Chat (Open WebUI) with MeweMarket's AI gateway; others not used:** of the hosted AI platforms checked, only Open WebUI (158k stars) can serve many companies from one server (groups per company; directory endpoints blocked at the proxy). It talks only to MeweMarket's OpenAI-compatible gateway, which uses each company's own Claude/OpenAI key (never stored in Open WebUI) and enforces the plan's monthly AI messages and a per-person rate; Claude is translated from/to OpenAI's format, streaming included. Licence: hostable and chargeable; branding must stay over 50 users (owner accepted). Not used: AnythingLLM (needs a container per company; owner chose to skip for now), Langflow (runs users' code by design), RAGFlow (~16 GB RAM, gaps), LibreChat (tenant mode unfinished), Dify/n8n/FastGPT (licences restrict hosting for others). The App Store gained an "AI" category (AI Chat, AI Assistant).
